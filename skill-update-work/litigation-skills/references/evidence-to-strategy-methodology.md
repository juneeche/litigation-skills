# Evidence To Strategy Methodology

This reference distills the user's litigation case folder into a reusable reasoning method.

## Core Chain

```text
客户目标 -> 法律关系定性 -> 请求权/抗辩要件 -> 证据功能分类 -> 金额与事实链校验 -> 文书表达 -> 庭审/质证策略
```

## Six Evidence Functions

| Function | Typical Materials | Litigation Use |
| --- | --- | --- |
| 法律关系 | 合同、借条、定点协议、采购单、委托聊天、劳动合同、既有判决 | 案由、主体资格、请求权基础 |
| 履行事实 | 交货单、签收单、工资流水、考勤、物流、发票、收据 | 证明我方履行或对方受领利益 |
| 金额计算 | 对账单、报价单、成本表、工资表、本息表、维修费 | 支撑诉请金额、扣减、保全金额 |
| 违约/抗辩 | 催款函、取消通知、质量照片、行政处理决定、聊天记录 | 证明违约或形成抗辩 |
| 因果与损失 | 维修发票、返场运费、客户投诉、检测报告、损失表 | 连接违约与损失 |
| 程序节点 | 传票、通知、判决、裁定、执行文书、送达材料 | 时效、管辖、重复起诉、执行路径 |

## Plaintiff-Side Pattern

1. 证明法律关系成立.
2. 证明我方履行或提供价值.
3. 证明对方违约或未履行.
4. 证明金额计算依据.
5. 证明催告或协商未果.
6. 转化为诉请、事实与理由、证据目录.

## Defendant-Side Pattern

1. 重定性法律关系.
2. 拆解对方请求权要件.
3. 找出要件缺口.
4. 对金额、履行、质量、时效、主体、程序进行抗辩.
5. 认可低阶事实但否认高阶证明目的.
6. 转化为答辩状和质证意见.

## Cross-Examination Formula

```text
对真实性/合法性予以认可或不予认可；对关联性及证明目的不予认可。
该证据至多证明【低阶事实】，不能证明【对方主张的高阶法律事实】。
结合我方证据【编号/名称】，应认定【我方事实】。
对方仍应就【关键要件】承担举证责任。
```

## Common Moves From The User's Cases

- 转账记录可证明付款，但不当然证明买卖关系；结合聊天可能重定性为委托代购、借款、投资或其他关系。
- 产品照片可证明外观，但没有检测/鉴定通常不能直接证明质量违法或食品安全问题。
- 单方工资、考勤、休假表缺少原始系统数据或签字确认时，可攻击真实性和证明力。
- 合同纠纷中，报价、对账、交付、催告构成诉请金额链；质量缺陷、迟延、取消项目、维修费构成扣减链。
- 劳动仲裁中，既有判决、行政处理决定、银行流水、考勤记录、解除时间和仲裁时效是关键节点。
- 合伙/代持/股权类案件优先审查共同出资、共同经营、收益共享、风险共担、代持合意和登记事实。

## Standard Deliverables

- 诉讼方案.
- 证据矩阵.
- 起诉状/答辩状结构.
- 证据目录证明目的.
- 质证意见.
- 补证清单.
- 庭前争议焦点.
